TRACE: Consolidating Embodied Experience into Executable On-Device Skills

#19 Submitted to MobiCom 2027

Demo Video

Abstract

Embodied agents must often execute onboard, where cloud offloading is constrained by network dependence and communication latency. Yet making models smaller does not necessarily make onboard execution efficient. Complex embodied tasks require step-by-step decisions based on live observations, making repeated model inference the dominant source of execution latency.

The key idea of TRACE is to compile recurring decision structures while preserving their observation dependencies, enabling adaptive on-device skill replay over live inputs without repeated model inference. TRACE connects heterogeneous perception and control operations through a unified cross-modal tool interface and extracts guarded skill graphs from noisy successful traces. Unlike static textual skills or fixed workflows, these graphs encode observation-conditioned control flow and data dependencies for runtime adaptation. At runtime, a router gates skill replay by applicability and reliability, while unfamiliar requests and replay deviations fall back to model-based reasoning from the current state, preserving partial progress for recovery and skill updates.

Across four public datasets, three simulators, and two physical testbeds, TRACE reduces end-to-end latency by 42.7% while preserving task accuracy, and avoids up to 51.1% of model generations and 45.5% of generated tokens.

Key Problem

  • Embodied agents must often execute onboard — cloud offloading is constrained by network dependence and communication latency.
  • Complex tasks are decided step by step on live observations — each sensing or action step invokes the model again, so repeated inference dominates end-to-end latency.
  • Model compression addresses only part of this overhead — it reduces the cost of each invocation, not how many invocations a task needs.
Key insight. On-device latency is set by how many times the agent has to think, not by how large the model is, so compressing the model leaves most of the execution overhead untouched.

Motivation

  • Sensing must be selected online. A task touches only 2.1 of 11 capability categories; fusing every stream takes 3.3× longer, and a one-pass omni-modal model reaches just 32.4% — a missed window (figure above) never comes back.
  • One recorded chain does not transfer. 67.3% of task groups need more than one sensing sequence, and fixing a sensor subset per task loses 13.1 points — the next step depends on the current observation.
  • What repeats is the structure. Inter-step reasoning costs 57–84% of generated tokens, yet the 100 most frequent chain patterns cover 64–71% of successes — so TRACE compiles the recurring structure and keeps each decision bound to live inputs.
Key insight. What recurs across instances is the decision structure, not the realized sequence. Reuse is therefore safe only if the structure is replayed while every decision inside it stays bound to live observations.

How TRACE Works

  1. Task. The user issues a request to the on-device agent — a question, a monitoring job, or an action to perform.
  2. Route. A reliability-gated router sends the task down one of two paths, both driving the same cross-modal tool pool:
    • Omni Brain — unfamiliar task: the 2B model composes sensing and action tools step by step, one model call per decision.
    • Skill Library — recurring task: a guarded skill graph replays with no model call between steps, its guards branching on live tool results.
  3. Assistance. The resulting sensing chain executes over the live streams and returns the answer or act to the user.
  4. Update. The outcome flows back into the library: successful chains are compiled into new skills, and unreliable ones lose admission, so the fast path keeps improving after deployment.
Key insight. This division accelerates recurring execution while retaining full model-based adaptability when reusable experience does not apply, and completed outcomes refine later admission and compilation — closing the loop between fast-path efficiency and slow-path adaptability.
